# ONNX 跨平台主体清晰度分析设计

## 目标

在不改变选片工作台界面和操作流程的前提下，用统一、离线、可随安装包分发的 ONNX 分析链替换 MediaPipe 主体检测链，并降低大光圈照片因背景虚化而被错误标记为“建议复查”的概率。

## 已确认的平台和交付约束

- macOS 最低版本为 macOS 12 Monterey，同时支持 Intel x86_64 和 Apple Silicon arm64。
- Windows 最低版本为 Windows 10 22H2，仅支持 64 位；同时支持 Windows 11。
- 主体检测模型随安装包交付，安装后无需联网下载。
- 核心分析不得依赖 Apple Vision、Core ML、WinML 或其他单一平台 API。
- Apple Vision 等平台加速只能作为未来可选插件，不能影响默认结果。
- 软件界面、导入、浏览、人工标记、筛选、导出及数据库工作流保持不变。

## 本次范围

本次改造只覆盖内部技术分析链及其直接依赖：

1. 使用 ONNX Runtime CPU 后端替换 MediaPipe Tasks。
2. 使用 YuNet ONNX 检测人脸和五点面部关键点。
3. 使用 YOLOX-Nano ONNX 检测人物、动物和常见物体。
4. 融合重叠的人脸、人物和物体候选框，继续向现有 `SubjectLocator` 和 `FocusAnalyzer` 输出 `SubjectCandidate`。
5. 优化主体区域清晰度计算和无主体时的保守降级策略。
6. 将技术分析算法版本升级为 `technical-v8`，旧结果继续可读。
7. 从运行时依赖和 macOS 安装包配置中移除 MediaPipe。
8. 从技术分析链中移除 OpenCV，并使用 Pillow、NumPy 实现读取、缩放、颜色转换及清晰度算子；完成后删除项目的 OpenCV 运行时依赖。
9. 更新模型来源、摘要、许可证和第三方声明。

HEIC/AVIF 的只解码构建、Windows 安装器和 macOS 通用安装器属于独立发布子项目，不纳入本次算法迁移。现有格式支持不得因本次迁移而回退。

## 架构

### 1. 图像上下文

`AnalysisContext` 继续提供全分辨率彩色图、灰度图、主体定位缩略图和 AF 提示。为限制调用方改动，现有字段名称和归一化坐标约定保持不变。

`image_reader` 使用 Pillow 读取 JPEG、PNG、TIFF、WebP 等普通格式，使用 rawpy 读取 RAW。Pillow 解码后的 RGB 数组在边界处转换为现有代码期望的 BGR 数组。缩放使用 Pillow 的 LANCZOS/BOX 重采样，灰度转换使用固定 BT.601 权重，保证 macOS 与 Windows 产生一致结果。

### 2. ONNX 推理后端

`OnnxSubjectBackend` 是唯一的默认主体推理后端。它惰性创建两个 ONNX Runtime CPU 会话：

- `face_detector`：OpenCV Zoo YuNet ONNX。输出人脸框、置信度及五个面部关键点。
- `object_detector`：官方 YOLOX-Nano 转换得到的固定 416×416 ONNX。输出 COCO 类别、置信度和物体框。

两个模型通过现有模型清单按 SHA-256 校验。运行时不进行网络访问。会话创建、输入预处理和输出解析分别放在小型、可独立测试的组件中；测试通过注入假会话验证真实数组输入输出，而不模拟上层业务结果。

推理统一使用 CPU Execution Provider。硬件加速不属于本次范围，以确保旧 Mac 和不同 Windows 显卡得到一致行为。

### 3. 主体候选融合

`SubjectLocator` 保留公开调用方式 `locate(context)`，但检测来源从 `face / pose / object` 收敛为 `face / object`。

候选处理规则如下：

- 人脸始终具有最高类型优先级。
- 位于人物框内的人脸与该人物视为同一主体，人脸框用于精细清晰度判断，人物框用于主体显著度和竞争关系判断。
- 高 IoU 的同类别物体按非极大值抑制结果去重。
- 两个显著度接近且空间分离的主体继续视为“无唯一主主体”，避免武断选择。
- 单一高置信度人脸、人物、动物或物体可成为主主体。
- 单个检测器失败时保留另一个检测器的结果并记录诊断；两个检测器均失败时分析返回“建议复查”，不得把能力故障判断为照片失焦。

`SubjectLocationResult` 的字段保持不变；`failed_sources` 允许值改为 `face` 和 `object`。旧的姿态模型和姿态检测分支被删除。

### 4. 主体优先清晰度

相机提供可用 AF 区域时，现有 AF 优先路径保持最高优先级。

没有 AF 区域时，清晰度区域按以下顺序选择：

1. 人脸：使用双眼、鼻部和面部中心形成的内缩区域；关键点不可用时使用人脸框中央区域。
2. 人物：使用人物框上部和中央内缩区域，避免大面积服装边缘或框内背景主导结果。
3. 动物和其他物体：使用物体框中央 70% 区域，降低边缘背景的权重。
4. 无主主体：把画面划分为重叠网格，选取有有效纹理的若干区域进行聚合；中心区域权重略高，但不假设主体一定居中。

拉普拉斯方差、Tenengrad 和纹理标准差由 NumPy 实现。计算使用与当前阈值量纲一致的卷积核，先通过现有合成测试建立数值等价范围，再使用真实样本重新校准阈值。

决策保持保守：

- 主体区域达到清晰阈值可判为“清晰”，即使背景大面积虚化。
- 只有在主体置信度高且多个清晰度指标一致偏低时才能判为“明显失焦”。
- 低纹理、区域过小、多主体冲突、检测器异常或指标相互矛盾均判为“建议复查”。

### 5. 模型和许可证

模型只能由仓库脚本从记录的上游 URL 获取。清单记录模型名称、上游版本、URL、SHA-256、文件大小和目录级许可证。

- YuNet 采用其 OpenCV Zoo 模型目录中的 MIT 许可证。
- YOLOX-Nano 采用官方 YOLOX 项目 Apache-2.0 许可证；转换脚本记录输入检查点摘要、导出参数和生成的 ONNX 摘要。
- ONNX Runtime 使用 MIT 许可证，并将许可证及第三方声明纳入发布材料。

发布审计不得仅依据包名推断权利。模型文件、其目录许可证、转换过程和最终二进制摘要必须能相互对应。

## 数据流

```text
文件路径
  -> Pillow/rawpy 离线解码
  -> AnalysisContext（全尺寸灰度 + 受限长边定位图）
  -> OnnxSubjectBackend
       -> YuNet 人脸与关键点
       -> YOLOX-Nano 人物/动物/物体
  -> SubjectLocator 融合、排序、故障记录
  -> FocusAnalyzer
       -> AF 区域（若可用）
       -> 主体内部区域
       -> 多区域兜底
  -> technical-v8 结果
  -> 现有保存、展示和导出流程
```

## 错误处理与降级

- 模型缺失或摘要不匹配：该检测来源失败并记录明确诊断；不得联网修复。
- ONNX Runtime 不可导入或会话创建失败：技术分析任务失败并显示现有任务错误状态，不得导致应用启动失败。
- 单模型输出形状、数值或类别无效：忽略无效候选并记录来源诊断。
- 单个模型失败：使用另一个模型继续分析。
- 两个模型失败且无 AF 区域：输出“建议复查”，证据标记能力不可用。
- 普通图片或 RAW 解码失败：沿用现有失败路径和错误显示。

## 兼容性

- `TechnicalAnalysisResult` 序列化结构不变，仅当前版本从 `technical-v7` 升级为 `technical-v8`。
- `technical-v3` 至 `technical-v7` 结果继续可读取；旧结果不会自动伪装成新算法结果。
- UI 文案和三种清晰度结论不变。
- 已有项目数据库不需要模式迁移。

- 默认分析服务创建 ONNX 后端而非 MediaPipe 后端。
- 在无网络环境中从安装资源加载两个模型并完成一次推理。
- 构建产物包含 ONNX Runtime、两个模型和许可证，不包含 MediaPipe 或 OpenCV。
- 普通图片和 RAW 的读取尺寸、方向及颜色行为保持兼容。
